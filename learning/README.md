# 学习工作区

`learning/` 保存需要长期维护的学习使命、课程安排、课件、课程专用练习、资料索引和学习证据。这里不是独立实验、
外部源码、构建输出或临时笔记的收集目录。

## 文件放在哪里

| 内容 | 目录 | 判断标准 |
| --- | --- | --- |
| 学习使命、课程、课件、学习记录 | `learning/<topic>/` | 围绕一个明确学习目标，后续仍需复习或更新 |
| 课程专用短练习 | `learning/<topic>/exercises/` | 只服务于该课程，并与课件和评分标准共同修改 |
| 临时验证、机器状态、完整构建日志 | `.scratch/` | 可以重新生成，不需要进入 Git 历史 |
| 有独立运行环境的实验 | `labs/` | 围绕明确问题或假设，可以独立运行和验证 |
| 稳定软件包 | `packages/` | 其他代码通过公开接口依赖，能独立构建并通过消费方测试 |
| 可执行工具 | `tools/` | 人或自动化系统直接启动，重复工作流程和退出行为明确 |
| 外部参考源码 | `references/` | 确有长期保留价值，并通过 Git submodule 固定版本 |
| 仓库级研究结论和规则 | `docs/` | 对多个学习主题或工程模块都适用 |

学习任务产生的代码不因为“来自课程”就自动留在 `learning/`。只有与某一课共同演进的最小练习进入
`exercises/`；需要独立依赖或回答课程之外问题的实现进入根 `labs/`。出现稳定代码调用方后迁入 `packages/`，
形成由人或自动化系统重复执行的流程后迁入 `tools/`。

## 单个学习工作区

每个主题只维护一个当前使命，使用以下最小结构：

- `MISSION.md`：为什么学习，以及可以观察的成功表现。
- `CURRICULUM.md`：顺序、时间预算、任务和检查标准。
- `RESOURCES.md`：经过筛选的一手资料和可提供实践反馈的社区。
- `NOTES.md`：不会被前三个文件替代的稳定教学规则；不保存每日活动流水。
- `lessons/`：短课和即时反馈材料。
- `exercises/`：仅在课程确需可执行练习时创建；每项练习带离线检查。
- `learning-records/`：学习者已经用回答或实践证明掌握的非显然知识。

案例、速查资料、Anki 卡片和阶段成果只在确有需要时增加对应目录，不创建空目录占位。

## 恢复学习

1. 先读主题的 `README.md` 和 `MISSION.md`，确认目标仍然有效。
2. 从 `learning-records/` 判断已经证明掌握的内容，不因课件存在就假定已经学会。
3. 按 `CURRICULUM.md` 找到下一项未通过的检查，并运行上次保存的最小验证命令。
4. 课程专用短练习放 `exercises/`；其余可复现实现进入 `labs/`、`packages/` 或 `tools/`，不要复制两份。
