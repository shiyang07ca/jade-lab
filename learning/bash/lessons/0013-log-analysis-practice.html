实战：日志分析与监控脚本

从零构建一个经过离线测试的日志分析练习——综合前 12 课知识

日志分析是部署脚本之外第二高频的 Bash 使用场景。报错时你需要：快速找出最近的错误、统计错误类型分布、判断是否在恶化。本课带你从 0 行代码起步，逐步迭代出一个完整的 analyze-log.sh——每一行代码都标注了对应的知识来源课。

2. 版本 1：最简错误扫描（第 7 课：grep）

# analyze-log.sh v1 — 最简单的版本
cat > /tmp/analyze-log-v1.sh << 'EOF'
#!/bin/bash
set -euo pipefail                                    # L8

LOG_FILE="${1:?用法: $0 <日志文件>}"                  # L4: 参数展开 + ${:?}

echo "=== 日志分析：$(basename "$LOG_FILE") ==="
echo ""

echo "--- ERROR 和 FATAL ---"
grep -E "\[ERROR\]|\[FATAL\]" "$LOG_FILE" || echo "  (无)"
echo ""

echo "--- 统计各级别数量 ---"
# L7: awk 提取级别列 + sed 去括号；反斜杠后不能再放注释
awk '{print $3}' "$LOG_FILE" | sed 's/\[//;s/\]//' \
    | sort | uniq -c | sort -rn

echo ""
echo "--- 最近的 5 条 WARN/ERROR/FATAL ---"
grep -E "\[WARN\]|\[ERROR\]|\[FATAL\]" "$LOG_FILE" \
    | tail -5 \
    || printf '  (无)\n'
EOF
bash /tmp/analyze-log-v1.sh /tmp/app.log
v1 已经是一个可用的工具了。 20 行代码，但涵盖了严格模式、参数检查、管道、grep/awk/sed。最重要的是——它不是写出来的，是迭代出来的。你先在终端手动敲一条 grep，好用就放进去；需要计数就加 awk+sort+uniq。脚本就是这样成长起来的。

3. 版本 2：加上时间段过滤和结构化报告

# analyze-log.sh v2 — 支持时间范围过滤，输出更结构化
cat > /tmp/analyze-log-v2.sh << 'SCRIPT'
#!/bin/bash
set -euo pipefail                                    # L8

# ===== 参数解析 =====
LOG_FILE="${1:?用法: $0 <日志文件> [开始时间] [结束时间]}"  # L4
START_TIME="${2:-}"                                    # L4: 参数展开默认值
END_TIME="${3:-}"

# ===== 工具函数 =====
die() { echo "[FATAL] $*" >&2; exit 1; }               # L8 + L6

# ===== 数据准备 =====
[[ -f "$LOG_FILE" ]] || die "文件不存在: $LOG_FILE"   # L5: [[ -f ]]

# 如果指定了时间范围，先用 awk 过滤（L7: awk 按条件筛选行）
if [[ -n "$START_TIME" || -n "$END_TIME" ]]; then      # L4 + L5
    # L7: awk -v 传变量；这里只比较固定宽度 HH:MM，不是通用时间解析
    FILTERED=$(awk -v start="${START_TIME:-00:00}" \
                    -v end="${END_TIME:-23:59}" '
        { split($2, t, ":"); time = t[1]":"t[2] }
        time >= start && time <= end
    ' "$LOG_FILE")
else
    FILTERED=$(<"$LOG_FILE")
fi

# ===== 核心分析 =====
TOTAL=$(printf '%s' "$FILTERED" | awk 'END { print NR + 0 }')
ERROR_COUNT=$(printf '%s' "$FILTERED" | awk '/\[ERROR\]/ { n++ } END { print n + 0 }')
WARN_COUNT=$(printf '%s' "$FILTERED" | awk '/\[WARN\]/ { n++ } END { print n + 0 }')
FATAL_COUNT=$(printf '%s' "$FILTERED" | awk '/\[FATAL\]/ { n++ } END { print n + 0 }')

# ===== 输出报告 =====
cat << REPORT                                         # L3: heredoc
╔══════════════════════════════════════════╗
║       日志分析报告                        ║
╠══════════════════════════════════════════╣
║  文件:  $(basename "$LOG_FILE")                   ║
║  总行数: $TOTAL                                   ║
║  时间范围: ${START_TIME:-全部} — ${END_TIME:-全部} ║
╠══════════════════════════════════════════╣
║  ERROR: $ERROR_COUNT  |  WARN: $WARN_COUNT  |  FATAL: $FATAL_COUNT  ║
╚══════════════════════════════════════════╝
REPORT

echo ""
echo "=== 错误详情（最近 10 条）==="
printf '%s\n' "$FILTERED" | grep -E "\[ERROR\]|\[FATAL\]" | tail -10 \
    || printf '  (无)\n'

echo ""
echo "=== 趋势分析 ==="
echo "$FILTERED" | awk '{print $3}' | sed 's/\[//;s/\]//' \
    | sort | uniq -c | sort -rn \
    | awk '{printf "  %-6s  %s\n", $2, $1}'             # L7: awk printf 格式化
SCRIPT
bash /tmp/analyze-log-v2.sh /tmp/app.log "08:05" "08:19"

4. 版本 3：加异常检测和告警

最终版以仓库中的 可执行脚本 为准，并由 离线测试 覆盖正常输入和参数失败。下面保留核心实现用于走读。

# analyze-log.sh v3 — 最终版：异常检测 + 阈值告警 + 可复用函数
cat > /tmp/analyze-log.sh << 'SCRIPT'
#!/bin/bash
set -euo pipefail                                    # L8

# ===== 工具函数必须先定义，参数错误才能调用 =====
die()   { echo "[FATAL] $*" >&2; exit 1; }
info()  { echo "[$(date '+%H:%M:%S')] $*"; }
warn()  { echo "[WARN] $*" >&2; }

[[ $# -ge 1 ]] || die "用法: $0 <日志文件> [--alert-threshold N] [--webhook URL]"
readonly LOG_FILE="$1"
shift                                                 # L5: shift 移走 $1

# ===== 参数解析 =====                               # L5: while + case
ALERT_THRESHOLD=10
WEBHOOK_URL=""
while [[ $# -gt 0 ]]; do
    case "$1" in
        --alert-threshold)
            [[ $# -ge 2 ]] || die "--alert-threshold 缺少值"
            ALERT_THRESHOLD="$2"; shift 2 ;;
        --webhook)
            [[ $# -ge 2 ]] || die "--webhook 缺少值"
            WEBHOOK_URL="$2"; shift 2 ;;
        *) die "未知参数: $1" ;;
    esac
done
[[ $ALERT_THRESHOLD =~ ^[0-9]+$ ]] || die "阈值必须是非负整数"

# ===== 核心分析函数 =====
scan_errors() {                                       # L6: 函数返回字符串
    awk '$3 == "[ERROR]" || $3 == "[FATAL]"' "$LOG_FILE"
}

count_by_level() {                                    # L7: awk + sort + uniq
    awk '{print $3}' "$LOG_FILE" | sed 's/\[//;s/\]//' \
        | sort | uniq -c | sort -rn
}

is_second_half_denser() {                             # 按行数归一化的密度启发式
    local level="$1"
    local total midpoint
    total=$(awk 'END { print NR + 0 }' "$LOG_FILE")
    (( total >= 2 )) || return 1
    midpoint=$((total / 2))
    awk -v expected="[$level]" -v midpoint="$midpoint" '
        NR <= midpoint && $3 == expected { first++ }
        NR > midpoint && $3 == expected { second++ }
        END {
            first_lines = midpoint; second_lines = NR - midpoint
            exit !((second + 0) * first_lines > (first + 0) * second_lines)
        }
    ' "$LOG_FILE"
}

# ===== 告警 =====                                   # L11: curl webhook
send_alert() {
    [[ -z "$WEBHOOK_URL" ]] && return 0
    local msg="$1"
    command -v jq >/dev/null || { warn "缺少 jq，跳过通知"; return 0; }
    command -v curl >/dev/null || { warn "缺少 curl，跳过通知"; return 0; }
    local payload
    payload=$(jq -n --arg text "[日志告警] $msg" '{text: $text}') \
        || { warn "JSON 构造失败"; return 0; }
    curl -fsS --connect-timeout 3 --max-time 10 \
        -H 'Content-Type: application/json' \
        --data "$payload" "$WEBHOOK_URL" > /dev/null \
        || warn "通知发送失败"
}

# ===== 主入口 =====
main() {
    [[ -f "$LOG_FILE" ]] || die "文件不存在: $LOG_FILE"

    info "开始分析: $(basename "$LOG_FILE")"

    # 1. 基本统计
    local total errors warns fatals
    total=$(awk 'END { print NR + 0 }' "$LOG_FILE")
    errors=$(awk '$3 == "[ERROR]" { n++ } END { print n + 0 }' "$LOG_FILE")
    warns=$(awk '$3 == "[WARN]" { n++ } END { print n + 0 }' "$LOG_FILE")
    fatals=$(awk '$3 == "[FATAL]" { n++ } END { print n + 0 }' "$LOG_FILE")

    # 2. 输出报告
    cat << REPORT
═══════════════════════════════════════
  日志分析: $(basename "$LOG_FILE")
═══════════════════════════════════════
  总行数:  $total
  ERROR:   $errors
  WARN:    $warns
  FATAL:   $fatals
  严重率:  $(( (errors + fatals) * 100 / (total > 0 ? total : 1) ))%
═══════════════════════════════════════
REPORT

    # 3. 级别分布
    echo ""; echo "--- 级别分布 ---"
    count_by_level

    # 4. 高频错误模式
    echo ""; echo "--- 高频错误消息 ---"
    scan_errors | awk '{$1=$2=$3=""; sub(/^ +/, ""); print}' \
        | sort | uniq -c | sort -rn | head -5

    # 5. 趋势检查 (L5: if)
    echo ""
    for level in ERROR WARN FATAL; do
        local count
        count=$(awk -v expected="[$level]" '$3 == expected { n++ } END { print n + 0 }' "$LOG_FILE")
        [[ $count -eq 0 ]] && continue

        if is_second_half_denser "$level"; then
            echo "⚠️  $level 在文件后半段的行密度更高"
        fi
    done

    # 6. 阈值告警 (L5: if + L11: webhook)
    if [[ $(( errors + fatals )) -ge $ALERT_THRESHOLD ]]; then
        echo ""
        echo "🚨 错误数 ($(( errors + fatals ))) 超过阈值 ($ALERT_THRESHOLD)！"
        send_alert "错误数 $(( errors + fatals )) 超过阈值 $ALERT_THRESHOLD（文件: $LOG_FILE）"
    fi

    info "分析完成"
}
main
SCRIPT
chmod +x /tmp/analyze-log.sh
/tmp/analyze-log.sh /tmp/app.log
/tmp/analyze-log.sh /tmp/app.log --alert-threshold 3

快速自检

Q1: 最终版为什么用 awk '... { n++ } END { print n + 0 }' 计数，而不直接用 grep -c ... || true？

因为 awk 总是比 grep 快 零匹配时明确输出 0，同时不把所有读取错误都用 true 掩盖 因为 grep 不能匹配方括号

Q2: v3 的 shift 在参数解析中的作用是什么？

删除脚本的第一个参数，让后续参数解析指向后面的内容 改变 shift 键的功能 重命名脚本的参数变量

Q3: is_second_half_denser() 实际判断的是什么？

计算每行的时间戳差值——如果间隔越来越短就是上升 按两段行数归一化后，比较某级别在后半段的行密度是否更高 用机器学习模型预测错误趋势

📖 推荐实践：把你项目里的一个真实日志文件拿过来，用 v3 脚本跑一下看看效果。然后修改 find_patterns() 来匹配你日志中的特定错误模式。
