第 13 课 ⏱ 约 35–50 分钟

日志分析器综合实践

以真实脚本、离线测试和明确输入格式整合前 12 课

本课不再复制一份容易漂移的“最终代码”。仓库中的 analyze-log.sh 是唯一实现，test.sh 是可重复证据。目标是解释它的输入、输出、状态和失败路径，并在测试保护下完成一次接口变更。

1. 完成标准

完成本课后，你应该能做到：

  • 不用逐行翻译，先画出参数解析、统计、报告和通知的执行路径。
  • 说明 stdout、stderr 和退出状态分别承载什么，以及 webhook 为什么不改变分析结果。
  • 解释日志格式假设、阈值边界、空文件、带空格路径和管道状态如何被测试。
  • 先写失败测试，再为工具添加一个小功能，并通过模块检查。
通过页面测验只证明能识别概念，不证明能维护脚本。课程证据是：测试先失败、实现后通过、ShellCheck/shfmt 通过，以及你能解释一次失败的根因。

3. 从第一性原理定义工具

问题本练习的明确答案
输入是什么？一个可读普通文件；每行以空白分隔，第三个字段是已知级别。
输出是什么？stdout 输出报告；stderr 输出参数、阈值和可选通知的诊断。
成功意味着什么？日志被读取并生成报告。达到阈值仍是成功分析，不自动变成程序失败。
哪些失败必须传播？参数无效、日志不可读、解析所需的本地命令失败。
哪些失败允许降级？webhook 是显式的 best-effort 附加通知；失败写 stderr，但不否定报告。

这里没有“通用日志格式”。如果输入改成 JSON Lines、字段顺序变化或消息允许多行，必须先改接口说明与测试夹具，再选择 jq、awk 或更合适的语言。

4. 四遍走读

  1. 扫结构：找到配置变量、parse_args、统计函数、send_alert 和 main。
  2. 追主干：main 先解析与验证输入，再统计、输出报告、比较密度和阈值。
  3. 查边界：重点读前导零归一化、awk 'NR <= 5'、稳定排序和 webhook 降级。
  4. 用测试证伪：为你认为会失败的输入增加用例，确认它先失败，再决定是否属于公开接口。

几个必须能解释的设计点

# 正则同时限制范围并去掉前导零；10# 明确使用十进制
[[ $ALERT_THRESHOLD =~ ^0*([0-9]{1,9})$ ]] || exit 1
ALERT_THRESHOLD=$((10#${BASH_REMATCH[1]}))

# 不用 head 提前关闭管道；在 pipefail 下，上游可能因 SIGPIPE 变成失败
... | awk 'NR <= 5'

# 零匹配仍输出 0；文件读取失败不会被宽泛的 “|| true” 隐藏
awk -v expected="[$level]" '
  $3 == expected { count++ }
  END { print count + 0 }
' "$LOG_FILE"
“后半段密度更高”只比较文件前后两段中某级别占行数的比例。它没有解析时间戳，所以不能推断单位时间错误率，更不能称为趋势预测。

5. 已完成的真实改动：--top N

本轮重构已按下面顺序为“高频严重消息”增加数量限制。请通过实现和测试复核每项，而不是只相信这份说明：

  1. 先在 test.sh 增加用例，证明旧实现不支持 --top。
  2. 定义接口：默认 5；只接受 1–100 的十进制整数；缺值、0、负数、过大和非数字都失败。
  3. 更新 usage 和参数解析，再把固定的 5 改为经过验证的变量。
  4. 增加至少 7 种不同严重消息，断言 --top 3 只输出 3 项。
  5. 运行 mise run check learning-bash，阅读全部输出。
不要用 eval 拼接 awk，也不要把未验证的 N 直接嵌入程序文本。用 awk -v limit="$TOP" 'NR <= limit' 把数据作为参数传入。

6. 迁移检验

选一份已脱敏的真实日志，先回答以下问题，再决定是否修改脚本：

  • 一条事件是否总是一行？时间、级别和消息的准确字段在哪里？
  • 未知级别和畸形行应忽略、计数还是使分析失败？
  • “严重率”的分母应是全部行、有效事件还是请求数？
  • 相同消息如何归一化：请求 ID、IP、数字和路径是否应被视为变量？

把答案写成一个最小夹具和断言。若规则开始包含多行事件、复杂时间窗口或多个输入源，应把 Bash 留作启动入口，把分析移到更适合的数据处理程序。

快速自检

Q1: 达到告警阈值时，脚本为什么仍可以返回 0？

因为阈值只是报告中的业务信号，分析本身仍成功 因为 Bash 不能返回非零 因为 stderr 会自动清除错误

Q2: 为什么不能把“后半段密度更高”称为时间错误率上升？

函数只按行切半，没有验证时间戳或时间跨度 因为 awk 不能处理数字 因为日志不能包含时间

Q3: 修改公开参数时，最有价值的第一步是什么？

先写一个会失败的接口测试，明确输入、输出和状态 先复制整个脚本作为 v4 先增加更多全局变量
