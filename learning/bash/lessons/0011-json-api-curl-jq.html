Bash 中处理 JSON 与 API

为 HTTP 设置失败与期限语义，用 jq 校验、提取和构造 JSON

自动化经常需要调用 HTTP API 并处理 JSON。这里学习 curl 的失败与期限选项，以及用 jq 做结构化解析和构造。查询“latest”只适合发现候选版本；进入可重复流程后还要记录并固定 tag、commit、校验和或镜像 digest。

1. curl：在命令行里发 HTTP 请求

curl 的选项很多；自动化先按接口需要定义 HTTP 失败、连接期限、总期限、响应体和认证，再选择对应选项：

# 最简 GET
curl https://api.example.com/health
OK

# 常用参数组合
curl -fsS --connect-timeout 2 --max-time 5 https://api.example.com/health
# -f: HTTP 错误返回非零；-sS: 隐藏进度但保留错误；两个 timeout 限制连接和总时长

自动化中常见的六个 curl 选项

参数 作用 为什么需要
-sS隐藏进度条，但仍显示错误脚本日志需要诊断信息
-fHTTP 400 及以上通常返回退出码 22默认传输成功的 404 响应仍可能返回 0
--connect-timeout N限制建立连接的时间和总请求期限是不同阶段
-H "Header: value"添加请求头JSON 要设 Content-Type，认证要带 Token
--data '{"key":"value"}'请求体；默认会选择 POST发送 JSON 等数据
--max-time N限制整个传输时间自动化不能无限等待
默认情况下，curl 完成 HTTP 404/500 响应的传输后仍可能返回 0。健康检查通常使用 -f 或需要响应体时使用 --fail-with-body，但认证状态等场景有文档说明的例外，仍应校验业务响应。配合 -s 时加 -S，避免隐藏诊断。

四类典型 curl 调用

# 1. 健康检查 GET —— 只关心 HTTP 状态码
if curl -fsS --connect-timeout 2 --max-time 5 http://localhost:8080/health > /dev/null; then
    echo "OK"
fi

# 2. 取 JSON 数据 GET —— 输出给 jq 解析
response=$(curl -fsS --connect-timeout 3 --max-time 10 \
    https://api.github.com/repos/kubernetes/kubernetes/releases/latest) || exit 1
jq -er '.tag_name | select(type == "string" and length > 0)' \
    <<< "$response"                                        # 分别检查 HTTP 与 JSON

# 3. 发 JSON 数据 POST —— 触发 Webhook、上报状态
curl -fsS --connect-timeout 3 --max-time 10 \
    -H "Authorization: Bearer ${DEPLOY_TOKEN:?必须设置 DEPLOY_TOKEN}" \
    -H 'Content-Type: application/json' \
    -d '{"status":"deployed","version":"v2.0"}' \
    https://hooks.example.com/deploy

# 4. 下载文件 —— 子 Shell 独占临时目录和 EXIT trap
(
    download_dir=$(mktemp -d) || exit 1
    trap 'rm -rf -- "$download_dir"' EXIT
    curl -fsSL --proto '=https' --proto-redir '=https' \
        -o "$download_dir/release.tar.gz" --connect-timeout 3 --max-time 120 \
        https://releases.example.com/app/v2.0.tar.gz || exit 1
    curl -fsSL --proto '=https' --proto-redir '=https' \
        -o "$download_dir/release.tar.gz.sha256" --connect-timeout 3 --max-time 10 \
        https://releases.example.com/app/v2.0.tar.gz.sha256 || exit 1
    (cd "$download_dir" && sha256sum -c release.tar.gz.sha256) || exit 1
)
# -o 指定输出文件；-L 跟随 HTTP 重定向
校验和能发现传输损坏，但如果文件与校验和来自同一个已被攻破的来源，不能证明发布者身份。高风险制品还应验证项目提供的签名或透明日志，并固定预期摘要。

2. jq：在命令行里查询 JSON

jq 之于 JSON，相当于 awk 之于表格文本、sed 之于普通文本——它是一门专门处理 JSON 的领域特定语言。部署脚本里用得最多的就是 jq 的查询和提取能力：

# 创建测试 JSON
demo_file=$(mktemp)
cat > "$demo_file" << 'EOF'
{
  "app": "myapp",
  "version": "2.3.1",
  "status": "running",
  "instances": [
    {"host": "srv1", "port": 8080, "healthy": true},
    {"host": "srv2", "port": 8080, "healthy": false},
    {"host": "srv3", "port": 8081, "healthy": true}
  ],
  "config": {
    "maxMemory": "512M",
    "replicas": 3
  }
}
EOF

# 基本提取
jq '.app' "$demo_file"             # → "myapp"（带引号的 JSON 字符串）
jq -r '.app' "$demo_file"          # → myapp（-r = raw——去引号，给 Bash 用）
jq '.config.replicas' "$demo_file" # → 3（嵌套取值）
-r（raw output）会让字符串不带 JSON 引号，适合传给 Bash。它不会验证字段存在或类型正确；缺失字段可能输出 null。边界数据应结合 -e、type 或 has 明确校验，例如 jq -er '.version | select(type == "string" and length > 0)'。

数组操作

jq '.instances[0]' "$demo_file"                     # 第一个元素
jq '.instances[0].host' "$demo_file"                # 第一个元素的主机名
jq '.instances[] | .host' "$demo_file"               # 所有元素的主机名（展开数组，每行一个）
"srv1"
"srv2"
"srv3"
jq -r '.instances[] | .host' "$demo_file"           # -r 去掉引号
srv1
srv2
srv3

过滤——jq 版的"WHERE"

# select(条件) —— 只保留符合条件的元素
jq '.instances[] | select(.healthy == true)' "$demo_file"
{ "host": "srv1", "port": 8080, "healthy": true }
{ "host": "srv3", "port": 8081, "healthy": true }

# 管道 + 值提取：只显示健康的实例名和端口
jq -r '.instances[] | select(.healthy) | "\(.host):\(.port)"' "$demo_file"
srv1:8080
srv3:8081

构造和转换

# 提取多个字段组成新对象
jq '{name: .app, ver: .version, count: .instances | length}' "$demo_file"
{ "name": "myapp", "ver": "2.3.1", "count": 3 }

# 只列出不健康的实例
jq '[.instances[] | select(.healthy == false)]' "$demo_file"
[{"host":"srv2","port":8080,"healthy":false}]

# 检查是否有不健康实例：-e 最后输出非 false/null 时为 0，false/null 为 1，无输出为 4
if jq -e '.instances[] | select(.healthy == false)' "$demo_file" > /dev/null; then
    echo "存在不健康的实例！"
fi
rm -f -- "$demo_file"

3. curl + jq 组合：实战模式

模式 A：获取 GitHub 最新 Release 版本号

get_latest_version() {
    local repo="$1"  # 例如 "cli/cli"
    local response

    [[ $repo =~ ^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$ ]] || return 2
    response=$(curl -fsS --connect-timeout 3 --max-time 10 \
        "https://api.github.com/repos/${repo}/releases/latest") || return 1
    jq -er '.tag_name | select(type == "string" and length > 0)' \
        <<< "$response"
}

LATEST=$(get_latest_version "cli/cli") || die "无法取得有效版本"
echo "最新版本: $LATEST"

模式 B：轮询部署状态——等 CI/CD 流水线完成

# 轮询一个 API 直到进入 succeeded 或 failed
# 知识点回顾：while（L5）+ curl -sf（本节）+ jq（本节）
wait_for_deploy() {
    local deploy_id="$1"
    local timeout="${2:-300}"
    local started=$SECONDS

    [[ $deploy_id =~ ^[A-Za-z0-9_-]{1,128}$ ]] \
        || { error "部署 ID 无效"; return 2; }
    [[ $timeout =~ ^[1-9][0-9]{0,5}$ ]] \
        || { error "期限必须是 1..999999 的整数秒"; return 2; }

    while (( SECONDS - started < timeout )); do
        local elapsed remaining request_timeout response status sleep_for
        elapsed=$((SECONDS - started))
        remaining=$((timeout - elapsed))
        request_timeout=$((remaining < 5 ? remaining : 5))

        response=$(curl -fsS --connect-timeout 2 --max-time "$request_timeout" \
            "https://api.ci.example.com/deploys/${deploy_id}") \
            || { error "状态 API 请求失败"; return 1; }
        status=$(jq -er '.status | select(type == "string")' <<< "$response") \
            || { error "状态响应不是预期 JSON"; return 1; }

        case "$status" in
            succeeded) info "部署成功"; return 0 ;;
            failed)    error "部署失败"; return 1 ;;
            *)         info "当前状态: $status ($((SECONDS - started))s)..." ;;
        esac
        remaining=$((timeout - (SECONDS - started)))
        (( remaining > 0 )) || break
        sleep_for=$((remaining < 5 ? remaining : 5))
        sleep "$sleep_for"
    done
    error "部署超时 (${timeout}s)"
    return 1
}
总期限要覆盖请求与轮询间隔，而不只是循环条件。这个例子把每次请求和休眠限制在剩余预算内；调度和命令开销仍可能造成少量误差。需要严格截止时间时，应使用单调时钟并在调用方再次检查。

模式 C：发送部署通知

notify_deploy() {
    local status="$1"    # success / failure
    local version="$2"
    local env="$3"
    local webhook_url="${WEBHOOK_URL:-}"

    if [[ -z "$webhook_url" ]]; then
        warn "未配置 WEBHOOK_URL，跳过通知"
        return 0
    fi
    case "$webhook_url" in
        http://*|https://*) ;;
        *) warn "WEBHOOK_URL 只接受 http/https URL"; return 0 ;;
    esac

    local timestamp payload
    timestamp=$(date -u '+%Y-%m-%dT%H:%M:%SZ') \
        || { warn "无法生成通知时间"; return 0; }
    # -n 不读输入；--arg 把 Bash 字符串按 JSON 规则转义
    payload=$(jq -n \
        --arg status "$status" \
        --arg version "$version" \
        --arg env "$env" \
        --arg time "$timestamp" \
        '{
            text: "部署 \($status)",
            version: $version,
            environment: $env,
            timestamp: $time
        }') || { warn "无法构造通知 JSON"; return 0; }

    if ! curl -fsS --connect-timeout 3 --max-time 10 \
        --proto '=http,https' --header 'Content-Type: application/json' \
        --data-binary "$payload" --url "$webhook_url" > /dev/null; then
        warn "通知发送失败"
    fi
    return 0
}
不要用 Shell 字符串拼接构造 JSON。版本号若含双引号或换行，手工拼接会生成无效或含义变化的数据。用 jq 的 --arg 传入字符串，并对数值、布尔值等使用对应类型的构造方式。 Webhook URL 和认证头可能包含凭证；发送请求前应关闭 set -x，日志也不得记录这些原值。

模式 D：批量读取 JSON 配置

# config.json: {"targets":[{"host":"srv1","port":22},{"host":"srv2","port":2222}]}

# 先完整验证并落到临时文件，再用重定向喂循环，保留验证失败和循环状态
# 本片段假定它拥有当前脚本的 EXIT trap
targets_file=$(mktemp) || die "无法创建临时文件"
trap 'rm -f -- "$targets_file"' EXIT
jq -c '
    .targets
    | if type != "array" or length == 0 then error("targets must be a non-empty array")
      elif all(.[];
        (.host | type == "string" and length > 0)
        and (.port | type == "number" and . == floor and . >= 1 and . <= 65535)
      ) then .[]
      else error("invalid target")
      end
' config.json > "$targets_file" || die "目标配置无效"

failed=0
while IFS= read -r target; do
    host=$(jq -r '.host' <<< "$target")
    port=$(jq -r '.port' <<< "$target")
    info "部署到 $host:$port"
    deploy_to "$host" "$port" || failed=1
done < "$targets_file"
(( failed == 0 )) || die "至少一个目标部署失败"

4. jq 速查：最常用的 12 个表达式

  读取字段
  .field              字段值
  .a.b.c              嵌套取值
  .field?             字段可选（不存在不报错）
  .[0]                数组第一个元素
  .[]                 展开数组每个元素

  过滤与变换
  select(.x > 0)      过滤（保留符合条件的）
  map(.name)          对数组每个元素做映射
  {a: .x, b: .y}      构造新对象
  "\(.x)-\(.y)"       字符串插值（-r 配合使用）

  辅助
  length              数组长度 / 字符串长度
  keys                对象的所有键名
  -s                  把多行输入合并成数组（slurp）

5. 当没有 jq 时——选择真实解析器

不要用 grep 或 sed 解析 JSON：转义、空白、字段顺序和嵌套都会让正则方案产生错误。如果目标环境已有 Python，可以使用标准库；否则把 jq 固定为该模块的显式依赖：

# Python 是一个可选替代，不假定所有系统都有它
printf '%s\n' '{"a":1}' \
    | python3 -c 'import json, sys; value=json.load(sys.stdin)["a"]; print(value)'
如果脚本以 jq 为接口，就在模块环境或容器镜像中固定并检查 jq 版本，不要依赖新机器“碰巧已安装”。依赖的体积、动态库和供应链来源以所选发行包为准。

快速自检

Q1: 服务器成功完成传输并返回 HTTP 404；curl 未使用 -f 时通常返回什么？

退出码 0——HTTP 404 是一个成功获取到的响应 退出码 404——和 HTTP 状态码一致 退出码 1——curl 视任何非 200 响应为错误

Q2: 以下哪条命令正确地把 JSON 中 `version` 字段赋给了 Bash 变量？

VERSION=$(jq '.version' config.json) VERSION=$(jq -er '.version | select(type == "string" and length > 0)' config.json) VERSION=jq '.version' config.json

Q3: 为什么应该用 `jq -n --arg v "$VERSION"` 而不是字符串拼接来构造 JSON？

jq --arg 会加密变量值，更安全 --arg 能正确处理变量中的双引号、反斜杠等特殊字符，拼接会毁掉 JSON 结构 --arg 比字符串拼接运行速度快

Q4: 要遍历 JSON 数组 `[{"host":"a","port":80},{"host":"b","port":443}]` 中的所有 host，jq 表达式写什么？

jq '.[] | .host' jq '.[0].host' jq '.host[]'
