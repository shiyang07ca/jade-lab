控制流

让脚本拥有判断、循环和分支的能力

部署脚本需要做决策：部署成功还是失败？重试还是放弃？针对不同环境做不同配置？这些全靠控制流。你会在脚本里看到大量的 if、for、while 和 case——它们不是魔法，就是本节的内容。

1. if 不判断真假，它判断退出码

Bash 的条件位置执行命令列表，并根据退出状态选择分支；这与直接判断一个布尔对象的语言不同：

# Python/JS 思维（在 Bash 里是错的！）
# if (condition == true) { ... }

# Bash 的真实逻辑：
# if 后面跟着一条命令，命令成功（退出码 0）→ then 分支
#                         命令失败（退出码非 0）→ else 分支
if grep -q "ERROR" /var/log/app.log; then
    echo "发现错误！"
else
    echo "一切正常"
fi

# grep 找到匹配 → 退出码 0 → "发现错误！"
# grep 没找到   → 退出码 1 → "一切正常"
命令列表可以直接放在 if 后面。 if cd /tmp; then、if tar -xf backup.tar.gz; then、if curl -fsS --max-time 5 http://localhost/health; then 都通过退出状态决定分支。仍要查清每个命令的非零状态分别表示“正常未匹配”、输入错误还是运行故障。

2. test 命令和它的三个化身

比较字符串、检查文件存在这种“条件”由 test 完成。它是一个命令：条件为真返回 0，为假返回 1； 表达式无效等错误可以返回大于 1 的状态，因此调用方仍要区分“假”和“执行失败”：

# 对这个简单文件测试，三种写法表达同一条件：
test -f /etc/passwd          # test 命令
[ -f /etc/passwd ]          # [ 是 test 的命令形式之一（注意空格）
[[ -f /etc/passwd ]]        # Bash 条件命令；解析和运算符并不等同于 test
[ 是一个命令名，不是语法括号！所以 [ "$x" = "y" ] 必须带空格——["$x" 会被当成一个命令名。同理，] 是 [ 命令的最后一个参数，也必须前面有空格。记不记得住？想想 ls -l 命令和参数之间怎么写的，[ 也是一条命令。

最常用的测试条件

类别 写法 含义
文件测试 [ -f "$FILE" ] 文件存在且是普通文件
[ -d "$DIR" ] 是目录
[ -x "$FILE" ] 当前用户可执行该路径；目录上表示可搜索，不保证是普通文件
字符串测试 [ "$A" = "$B" ] 字符串相等
[ -z "$VAR" ] 字符串为空（zero length）
数值比较 [ "$N" -eq 5 ] 等于（-eq / -ne / -lt / -gt / -le / -ge）
[ "$N" -lt 10 ] 小于

[ ] vs [[ ]]：选哪个？

# [ ] 是 POSIX 接口，参数和引用规则需要明确处理：
[ "$A" = "$B" ]          # 引用展开，避免空值和通配展开改变参数
[ "$A" = "$B" -a "$C" = "$D" ]  # -a (and) 语法诡异

# [[ ]] 是 Bash 增强版——好写、安全、功能强：
[[ $A = "$B" ]]          # 变量可以不加引号（内部不做单词分割）
[[ $A = "$B" && $C = "$D" ]]  # && 和 || 直接用，直觉性满分
[[ $A =~ ^[0-9]+$ ]]      # 支持正则表达式匹配（=~）
实用建议：明确以 Bash 为运行时的脚本默认用 [[ ]]，它避免部分单词分割和路径名展开问题。需要兼容 POSIX sh 时使用 [ ]。Dockerfile 的 RUN 由镜像和 SHELL 指令决定解释器；Alpine 默认通常是 BusyBox ash，但这不是所有容器的统一规则。

3. if / elif / else：完整的条件分支

if [[ "$ENV" = "production" ]]; then
    echo "谨慎操作！"
elif [[ "$ENV" = "staging" ]]; then
    echo "可以大胆一点"
else
    echo "本地环境，随意折腾"
fi

# elif 可以有多个，else 和 elif 都是可选的
# 别忘了 fi 结束——它是 if 倒过来写

部署脚本里最常见的 if 模式：

# 模式 1：检查命令是否成功
if ! tar -xzf "$ARCHIVE" -C "$DIR"; then
    echo "解压失败！" >&2
    exit 1
fi

# 模式 2：检查必需的文件/目录是否存在
if [[ ! -f "$CONFIG_FILE" ]]; then
    echo "配置文件 $CONFIG_FILE 不存在" >&2
    exit 1
fi

# 模式 3：根据参数选择行为
if [[ "$1" = "--force" ]]; then
    FORCE=true
    shift   # shift 把参数列表左移（$2 变 $1，$3 变 $2...）
fi

4. for 循环：遍历一串东西

和 Python 的 for i in range(10) 不同，Bash 的 for 是遍历一个词列表：

# 模式 1：直接写列表
for fruit in apple banana orange; do
    echo "处理 $fruit"
done

# 模式 2：遍历文件通配；无匹配时先跳过字面模式
for log in "$LOG_DIR"/*.log; do
    [[ -e $log ]] || continue
    printf '将归档: %s\n' "$log"
done

# 模式 3：逐行读取，不用 for x in $(command) 破坏原始边界
while IFS=: read -r user _; do
    printf '用户: %s\n' "$user"
done < /etc/passwd

需要像 Python 那样数数字怎么做？

# {start..end} 大括号展开
for i in {1..5}; do
    echo "第 $i 次尝试"
    curl -fsS --connect-timeout 2 --max-time 5 https://api.example.com/health && break
    if [[ $i -lt 5 ]]; then sleep 2; fi
done

# Bash 算术循环：变量起点、终点和步长都可以计算
for ((i = 1; i <= 10; i += 2)); do
    printf '%s\n' "$i"
done
for f in *.txt 当没有任何 .txt 文件时，$f 的值是字面量 *.txt。 循环内应先检查展开结果，例如 [[ -f $f ]] || continue；也可以在受控作用域开启 shopt -s nullglob，并确认调用方是否依赖默认通配行为。

5. while 和 until：条件驱动的循环

# while: 条件为真（退出码 0）时继续循环
COUNT=0
while [[ $COUNT -lt 3 ]]; do
    echo "尝试连接... ($((++COUNT)))"
    curl -fsS --connect-timeout 1 --max-time 2 http://localhost:8080/health >/dev/null && break
    if [[ $COUNT -lt 3 ]]; then sleep 1; fi
done

# until: 条件为假（退出码非 0）时继续；函数状态区分就绪与超时
wait_until_ready() {
    local deadline=$((SECONDS + 30))
    until curl -fsS --connect-timeout 1 --max-time 2 http://localhost:8080/health >/dev/null; do
        ((SECONDS < deadline)) || return 1
        echo "等待服务就绪..."
        sleep 2 || return 1
    done
}
if wait_until_ready; then echo "服务已就绪！"; else echo "等待服务超时" >&2; fi
部署脚本里最经典的 while 模式——等待某个条件满足：等待数据库就绪、等待端口监听、等待健康检查通过。另一个经典模式——逐行读取文件：while IFS= read -r line; do echo "$line"; done < file.txt（这个我们会在后续课程深入）。

6. case：多路分支的模式匹配

case "$1" in
    start)
        echo "启动服务..."
        ;;
    stop)
        echo "停止服务..."
        ;;
    restart|reload)
        echo "重启服务..."
        ;;
    *)
        echo "用法: $0 {start|stop|restart}"
        exit 1
        ;;
esac

case 的模式使用 glob 通配符（不是正则！）：

case "$INPUT" in
    y|Y|yes|YES)     echo "确认" ;;
    n|N|no|NO)       echo "取消" ;;
    [0-9]*)          echo "以数字开头" ;;   # glob 模式：[0-9] 单个数字，* 任意字符串
    *.tar.gz|*.tgz)  echo "压缩包" ;;      # | 表示"或"
    *)               echo "未知输入" ;;
esac

7. && 和 ||：短路运算符

有时候你不需要完整的 if/then/fi，一行就够了：

# cmd1 && cmd2  —— cmd1 成功才执行 cmd2
cd /opt/app && ./deploy.sh        # cd 失败就不执行后面

# cmd1 || cmd2  —— cmd1 失败才执行 cmd2
grep -q "OK" /tmp/status || echo "没找到 OK" >&2

# 需要 if/else 语义时直接使用 if，避免中间命令失败改变分支
if curl -fsS --max-time 5 http://localhost/health; then echo "OK"; else echo "FAIL"; fi
&& 和 || 是短路运算，不是 if/else！ 回头看 cmd1 && cmd2 || cmd3：如果 cmd1 失败，cmd2 不执行（短路），然后 cmd3 执行。但如果 cmd1 成功、cmd2 也成功了，cmd3 也会执行吗？不会——因为 cmd2 成功返回 0，|| 发现左边已经"真"了，短路跳过 cmd3。但如果 cmd1 成功、cmd2 失败了，cmd3 也会执行！A && B || C 不等于 if/else，它等于"A 且 B 失败时，或 A 失败时，执行 C"。逻辑复杂时，老老实实用 if。

8. 实战：把这些组合成有用的脚本

#!/bin/bash
# deploy.sh — 一个简单的部署脚本
# 用法: ./deploy.sh [staging|production]

set -euo pipefail   # 第 8 课会解释这些选项的作用与例外

ENV="${1:-}"
BUILD_DIR="./build"
REMOTE_APP_DIR="/opt/myapp"

# 1. 参数检查
if [[ -z "$ENV" ]]; then
    echo "用法: $0 <staging|production>" >&2
    exit 1
fi

# 2. 环境分支
case "$ENV" in
    staging)
        SERVER="staging.example.com"
        ;;
    production)
        SERVER="prod.example.com"
        echo "⚠️  你正在操作生产环境！"
        read -r -p "确认？(yes/no) " CONFIRM
        [[ "$CONFIRM" != "yes" ]] && exit 0
        ;;
    *)
        echo "未知环境: $ENV" >&2
        exit 1
        ;;
esac

# 3. 前置检查
if [[ ! -d "$BUILD_DIR" ]]; then
    echo "本地构建目录不存在: $BUILD_DIR" >&2
    exit 1
fi

# 4. 部署循环——最多尝试 3 次
for i in {1..3}; do
    echo "部署尝试 $i/3 ..."
    if rsync -avz "$BUILD_DIR/" "$SERVER:$REMOTE_APP_DIR/"; then
        echo "✅ 部署成功"
        exit 0
    fi
    if [[ $i -lt 3 ]]; then
        echo "部署失败，等待 5 秒后再次尝试..."
        sleep 5
    fi
done

# 5. 循环结束 = 全部失败
echo "❌ 部署失败：3 次尝试均未成功" >&2
exit 1

快速自检

Q1: if grep "ERROR" app.log; then echo "有错"; fi——这个 if 什么时候输出"有错"？

grep 找到包含 ERROR 的行（退出码 0）时 grep 没找到包含 ERROR 的行（退出码 1）时 app.log 文件存在时

Q2: 下面哪个写法是错的？

[ "$A" = "$B" ] ["$A" = "$B"] [[ $A = "$B" ]]

Q3: 部署脚本中 for i in {1..3}; do curl api/health && break; sleep 2; done 是什么意思？

精确执行 curl 命令 3 次，每次间隔 2 秒 最多尝试 3 次：curl 成功就跳出循环，失败就等 2 秒再试 如果 curl 失败，重复 3 次；如果成功，直接退出脚本

Q4: case $ENV in start|restart) 中的 | 含义是？

正则表达式的"或"——匹配 start 或 restart Glob 模式的"或"——匹配 start 或 restart 管道——把 start 的输出传给 restart
