控制流

让脚本拥有判断、循环和分支的能力

部署脚本需要做决策：部署成功还是失败？重试还是放弃？针对不同环境做不同配置？这些全靠控制流。你会在脚本里看到大量的 if、for、while 和 case——它们不是魔法，就是本节的内容。

1. if 不判断真假，它判断退出码

这是 Bash 和其他语言最根本的区别：

# Python/JS 思维（在 Bash 里是错的！）
# if (condition == true) { ... }

# Bash 的真实逻辑：
# if 后面跟着一条命令，命令成功（退出码 0）→ then 分支
#                         命令失败（退出码非 0）→ else 分支
if grep -q "ERROR" /var/log/app.log; then
    echo "发现错误！"
else
    echo "一切正常"
fi

# grep 找到匹配 → 退出码 0 → "发现错误！"
# grep 没找到   → 退出码 1 → "一切正常"
任何命令都可以放在 if 后面。 if cd /tmp; then、if tar -xf backup.tar.gz; then、if curl -s http://localhost/health; then——它们都返回退出码，if 只看退出码。这个设计让 Bash 的 if 比大多数语言更直接：你不需要先"获取结果"再"判断"，你直接判断命令本身。

2. test 命令和它的三个化身

那你肯定想问：比较字符串、检查文件存在这种"条件"怎么做？答案是 test——它就是一个普通命令，根据条件返回 0 或 1：

# 三种写法，完全等价：
test -f /etc/passwd          # test 命令
[ -f /etc/passwd ]          # [ 是 test 的命令形式之一（注意空格）
[[ -f /etc/passwd ]]        # Bash 增强版，更安全（推荐）
[ 是一个命令名，不是语法括号！所以 [ "$x" = "y" ] 必须带空格——["$x" 会被当成一个命令名。同理，] 是 [ 命令的最后一个参数，也必须前面有空格。记不记得住？想想 ls -l 命令和参数之间怎么写的，[ 也是一条命令。

最常用的测试条件

类别 写法 含义
文件测试 [ -f "$FILE" ] 文件存在且是普通文件
[ -d "$DIR" ] 是目录
[ -x "$FILE" ] 是可执行文件
字符串测试 [ "$A" = "$B" ] 字符串相等
[ -z "$VAR" ] 字符串为空（zero length）
数值比较 [ "$N" -eq 5 ] 等于（-eq / -ne / -lt / -gt / -le / -ge）
[ "$N" -lt 10 ] 小于

[ ] vs [[ ]]：选哪个？

# [ ] 是 POSIX 标准，但功能弱、易出错：
[ "$A" = "$B" ]          # 引用展开，避免空值和通配展开改变参数
[ "$A" = "$B" -a "$C" = "$D" ]  # -a (and) 语法诡异

# [[ ]] 是 Bash 增强版——好写、安全、功能强：
[[ $A = "$B" ]]          # 变量可以不加引号（内部不做单词分割）
[[ $A = "$B" && $C = "$D" ]]  # && 和 || 直接用，直觉性满分
[[ $A =~ ^[0-9]+$ ]]      # 支持正则表达式匹配（=~）
实用建议：明确以 Bash 为运行时的脚本默认用 [[ ]]，它避免部分单词分割和路径名展开问题。需要兼容 POSIX sh 时使用 [ ]。Dockerfile 的 RUN 由镜像和 SHELL 指令决定解释器；Alpine 默认通常是 BusyBox ash，但这不是所有容器的统一规则。

3. if / elif / else：完整的条件分支

if [[ "$ENV" = "production" ]]; then
    echo "谨慎操作！"
elif [[ "$ENV" = "staging" ]]; then
    echo "可以大胆一点"
else
    echo "本地环境，随意折腾"
fi

# elif 可以有多个，else 和 elif 都是可选的
# 别忘了 fi 结束——它是 if 倒过来写

部署脚本里最常见的 if 模式：

# 模式 1：检查命令是否成功
if ! tar -xzf "$ARCHIVE" -C "$DIR"; then
    echo "解压失败！" >&2
    exit 1
fi

# 模式 2：检查必需的文件/目录是否存在
if [[ ! -f "$CONFIG_FILE" ]]; then
    echo "配置文件 $CONFIG_FILE 不存在" >&2
    exit 1
fi

# 模式 3：根据参数选择行为
if [[ "$1" = "--force" ]]; then
    FORCE=true
    shift   # shift 把参数列表左移（$2 变 $1，$3 变 $2...）
fi

4. for 循环：遍历一串东西

和 Python 的 for i in range(10) 不同，Bash 的 for 是遍历一个词列表：

# 模式 1：直接写列表
for fruit in apple banana orange; do
    echo "处理 $fruit"
done

# 模式 2：遍历文件通配
for log in /var/log/*.log; do
    echo "归档 $log"
    gzip "$log"
done

# 模式 3：遍历命令输出（关键：用 $() 生成列表）
for user in $(cut -d: -f1 /etc/passwd); do
    echo "用户: $user"
done

需要像 Python 那样数数字怎么做？

# {start..end} 大括号展开
for i in {1..5}; do
    echo "第 $i 次重试"
    curl -s https://api.example.com/health && break
    sleep 2
done

# seq 命令（更灵活）
for i in $(seq 1 2 10); do   # 1 到 10，步长 2 → 1, 3, 5, 7, 9
    echo $i
done
for f in *.txt 当没有任何 .txt 文件时，$f 的值是字面量 *.txt。 不会报错，但你会陷入困惑。安全写法：先检查文件存不存在——if [[ -f "$f" ]]; then，或开启 shopt -s nullglob（让无匹配的通配符展开成空）。

5. while 和 until：条件驱动的循环

# while: 条件为真（退出码 0）时继续循环
COUNT=0
while [[ $COUNT -lt 3 ]]; do
    echo "尝试连接... ($((++COUNT)))"
    nc -z localhost 8080 && break
    sleep 1
done

# until: 条件为假（退出码非 0）时继续循环（= while 的相反）
until curl -s http://localhost:8080/health; do
    echo "等待服务就绪..."
    sleep 2
done
echo "服务已就绪！"
部署脚本里最经典的 while 模式——等待某个条件满足：等待数据库就绪、等待端口监听、等待健康检查通过。另一个经典模式——逐行读取文件：while IFS= read -r line; do echo "$line"; done < file.txt（这个我们会在后续课程深入）。

6. case：多路分支的模式匹配

case "$1" in
    start)
        echo "启动服务..."
        ;;
    stop)
        echo "停止服务..."
        ;;
    restart|reload)
        echo "重启服务..."
        ;;
    *)
        echo "用法: $0 {start|stop|restart}"
        exit 1
        ;;
esac

case 的模式使用 glob 通配符（不是正则！）：

case "$INPUT" in
    y|Y|yes|YES)     echo "确认" ;;
    n|N|no|NO)       echo "取消" ;;
    [0-9]*)          echo "以数字开头" ;;   # glob 模式：[0-9] 单个数字，* 任意字符串
    *.tar.gz|*.tgz)  echo "压缩包" ;;      # | 表示"或"
    *)               echo "未知输入" ;;
esac

7. && 和 ||：短路运算符

有时候你不需要完整的 if/then/fi，一行就够了：

# cmd1 && cmd2  —— cmd1 成功才执行 cmd2
cd /opt/app && ./deploy.sh        # cd 失败就不执行后面

# cmd1 || cmd2  —— cmd1 失败才执行 cmd2
grep -q "OK" /tmp/status || echo "没找到 OK" >&2

# 组合使用：三元运算的效果
curl -s http://localhost/health && echo "OK" || echo "FAIL"
&& 和 || 是短路运算，不是 if/else！ 回头看 cmd1 && cmd2 || cmd3：如果 cmd1 失败，cmd2 不执行（短路），然后 cmd3 执行。但如果 cmd1 成功、cmd2 也成功了，cmd3 也会执行吗？不会——因为 cmd2 成功返回 0，|| 发现左边已经"真"了，短路跳过 cmd3。但如果 cmd1 成功、cmd2 失败了，cmd3 也会执行！A && B || C 不等于 if/else，它等于"A 且 B 失败时，或 A 失败时，执行 C"。逻辑复杂时，老老实实用 if。

8. 实战：把这些组合成有用的脚本

#!/bin/bash
# deploy.sh — 一个简单的部署脚本
# 用法: ./deploy.sh [staging|production]

set -euo pipefail   # 第 8 课会详细讲，先记住这是"严格模式"

ENV="${1:-}"
APP_DIR="/opt/myapp"

# 1. 参数检查
if [[ -z "$ENV" ]]; then
    echo "用法: $0 <staging|production>" >&2
    exit 1
fi

# 2. 环境分支
case "$ENV" in
    staging)
        SERVER="staging.example.com"
        ;;
    production)
        SERVER="prod.example.com"
        echo "⚠️  你正在操作生产环境！"
        read -p "确认？(yes/no) " CONFIRM
        [[ "$CONFIRM" != "yes" ]] && exit 0
        ;;
    *)
        echo "未知环境: $ENV" >&2
        exit 1
        ;;
esac

# 3. 前置检查
if [[ ! -d "$APP_DIR" ]]; then
    echo "应用目录不存在: $APP_DIR" >&2
    exit 1
fi

# 4. 部署循环——重试 3 次
for i in {1..3}; do
    echo "部署尝试 $i/3 ..."
    if rsync -avz ./build/ "$SERVER:$APP_DIR/"; then
        echo "✅ 部署成功"
        exit 0
    fi
    echo "部署失败，等待 5 秒后重试..."
    sleep 5
done

# 5. 循环结束 = 全部失败
echo "❌ 部署失败：已重试 3 次" >&2
exit 1

      ┌──────────────────────────────────────────────────┐
      │              控制流速查                            │
      │                                                  │
      │  if 命令; then ... fi   判断命令的退出码（0→then）│
      │  [[ "$A" = "$B" ]]        字符串相等              │

      │  for x in 列表; do ... done  遍历词列表      │
      │  for i in {1..10}        数字范围                │
      │  for f in *.txt          文件通配                │
      │                                                  │
      │  while [[ 条件 ]]; do ... done   条件真→循环      │
      │  until [[ 条件 ]]; do ... done   条件假→循环      │
      │                                                  │
      │  case $VAR in            Glob 模式多路分支       │

快速自检

Q1: if grep "ERROR" app.log; then echo "有错"; fi——这个 if 什么时候输出"有错"？

grep 找到包含 ERROR 的行（退出码 0）时 grep 没找到包含 ERROR 的行（退出码 1）时 app.log 文件存在时

Q2: 下面哪个写法是错的？

[ "$A" = "$B" ] ["$A" = "$B"] [[ $A = "$B" ]]

Q3: 部署脚本中 for i in {1..3}; do curl api/health && break; sleep 2; done 是什么意思？

精确执行 curl 命令 3 次，每次间隔 2 秒 最多重试 3 次：curl 成功就跳出循环，失败就等 2 秒再试 如果 curl 失败，重复 3 次；如果成功，直接退出脚本

Q4: case $ENV in start|restart) 中的 | 含义是？

正则表达式的"或"——匹配 start 或 restart Glob 模式的"或"——匹配 start 或 restart 管道——把 start 的输出传给 restart
