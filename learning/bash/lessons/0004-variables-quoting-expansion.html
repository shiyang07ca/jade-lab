变量、引用与展开

理解 Bash 在运行命令之前对你的文字做了什么

部署脚本里最常见的困惑：为什么 DIR=/opt/app 等号两边不能有空格？为什么变量要写 "${LOG_DIR}" 而不只是 $LOG_DIR？单引号和双引号到底有什么区别？这节课让你彻底搞明白。

1. Bash 在运行命令前做了什么？

这是理解变量的关键前提。当你按下回车，Bash 不是直接把你的输入发给命令——它先做一轮"展开"（expansion），把你写的文字替换成实际的值：

你输入：  echo "当前用户是 $USER，路径是 $(pwd)"
              │
              ▼  Bash 展开处理
              │  1. 大括号展开  {a,b,c} → a b c
              │  2. 波浪号展开  ~ → /home/you
              │  3. 变量展开    $USER → alice
              │  4. 命令替换    $(pwd) → /opt/app
              │  5. 单词分割    按 IFS 切分
              │  6. 文件名通配  *.txt → a.txt b.txt
              │  7. 引用移除    去掉引号
              ▼
命令看到：echo 当前用户是 alice，路径是 /opt/app

这个过程叫 expansion（展开）。变量、引号和命令替换都在这个阶段处理。命令本身永远看不到你写的原始文本——它只看到展开后的结果。

这解释了为什么 Bash 和 Python/JS 的变量行为完全不同。在 Python 里，变量是运行时的概念；在 Bash 里，变量替换发生在命令启动之前，由 Shell 完成。命令（如 echo）收到的已经是替换后的纯字符串。

2. 变量赋值：三条铁律

NAME="alice"             # ✅ 等号两边不能有空格
AGE=30                  # ✅ 数字不用引号也行
GREETING="hello world"   # ✅ 引号把含空格的值作为一个赋值词

NAME = "alice"           # ❌ Bash 以为 NAME 是个命令，"=" 和 "alice" 是参数
NAME= alice              # ❌ 把 NAME 设成空字符串，然后运行 alice 命令
铁律 说明
等号两边不能有空格 VAR=value，多了空格 Bash 就会误解
值有空格或特殊字符时应引用或转义 MSG="hello world" 最清晰；也可以逐字符转义
变量名由字母、数字、下划线组成，且不能以数字开头 app_home ✅，2nd_app 和 app-home ❌

3. 读取变量：$VAR 还是 ${VAR}？

echo $NAME            # → alice（最简写法）
echo ${NAME}          # → alice（带大括号，更安全）
echo "$NAME"          # → alice（双引号内照样展开）

那什么时候必须用大括号？

APP="myapp"
VERSION="v2"
echo $APP_$VERSION      # → v2 —— 等等，$APP 去哪了？
echo ${APP}_${VERSION}  # → myapp_v2 —— 正确！

# 原因：Bash 把 APP_ 当成一个变量名（没定义，所以空），只输出了 $VERSION
# 大括号明确告诉 Bash 变量名的边界在哪
什么时候必须加花括号？ 当变量名后面紧跟着字母、数字或下划线时——这些字符本身也是合法的变量名字符，Bash 会贪心地往后匹配。部署脚本里常见 ${APP_HOME}/logs、${VERSION}.tar.gz——养成默认加 ${VAR} 的习惯，安全又清晰。

4. 引用：本课最重要的一节

三种写法，三种行为：

         文本写成      变量展开？    命令替换？    单词分割？    通配展开？
         ─────────────────────────────────────────────────────────────
         '...' 单引号     ❌            ❌            ❌            ❌
         "..." 双引号     ✅            ✅            ❌            ❌
         无引号           ✅            ✅            ✅            ✅

单引号：一切按字面来

echo '$USER says $(date) and *.txt'
$USER says $(date) and *.txt

# 单引号里面，美元符号、反引号、星号……全部失去特殊含义
# 你写了什么，就是什么。一个字都不会变。

双引号：展开变量，但保护结构

echo "用户是 $USER，今天是 $(date +%m月%d日)"
用户是 alice，今天是 07月22日

# $VAR 和 $(cmd) 正常展开，但空格和通配符不会造成额外的分割或匹配

无引号：危险！

FILES="*.txt"
echo $FILES       # → a.txt b.txt c.txt（展开了通配符）
echo "$FILES"     # → *.txt（保留了原样）

MSG="hello   world"
echo $MSG         # → hello world（多个空格被"压扁"成一个）
echo "$MSG"       # → hello   world（空格保留）
默认用双引号包裹参数位置中的变量展开。 除非你明确需要单词分割或通配展开，否则写 "$VAR" 而不是 $VAR。ShellCheck 会在可能发生意外分割或通配展开的场景报告 SC2086，但赋值、[[ ]] 等上下文有不同规则。路径变量没加引号是常见 bug：cd $DIR 在 DIR 含空格时会拆成多个参数，而 cd "$DIR" 保持一个参数。

5. 命令替换：把命令的输出变成字符串

NOW=$(date)                  # $(...) 是现代写法，推荐
echo "现在是：$NOW"
现在是：2026年 7月22日 星期三 14时30分00秒 CST

TIMESTAMP=$(date +%Y%m%d_%H%M%S)
echo "备份文件：backup_${TIMESTAMP}.tar.gz"
备份文件：backup_20260722_143000.tar.gz

LINE_COUNT=$(wc -l < /var/log/app.log)   # 把命令输出存到变量里
echo "日志共 $LINE_COUNT 行"
你可能见过反引号写法：`date`。它的嵌套与转义规则更难读，新增脚本优先使用 $(...)。命令替换可以嵌套，例如 name=$(basename "$PWD")；仍需按所在上下文正确引用展开结果。

6. 特殊变量：Bash 给你的"免费变量"

以下是在脚本里出现频率最高的特殊变量：

变量 含义 部署脚本典型用法
$? 上一条命令的退出码 if [ $? -ne 0 ]; then echo "失败"; fi
$0 脚本自身的名字 echo "用法: $0 <参数>"
$1 … $9 第 1-9 个命令行参数 DEPLOY_ENV="$1" — 读取第一个参数
$# 参数个数 if [ $# -lt 1 ]; then echo "缺少参数"; exit 1; fi
"$@" 所有参数（每个保持独立） for arg in "$@"; do process "$arg"; done
"$*" 所有参数（用 IFS 首字符连接成一个字符串） 几乎不用，优先用 "$@"
可靠且最有用的差异出现在双引号内："$@" 让每个参数保持独立，例如 "a"、"b c"、"d" 三个参数；"$*" 用 IFS 的第一个字符把它们合成一个参数。转发参数时使用 "$@"。不加引号的 $@ 和 $* 还会发生单词分割与路径名展开，不能保持原始边界。

7. 实战：部署脚本里的变量模式

下面是一个典型部署脚本中你将会看到的变量用法——它们不是魔法，就是本节学的内容：

#!/bin/bash
# 典型的部署脚本片段——看看你认识多少种变量用法？

# 1. 变量赋值 + 命令替换
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
APP_DIR="/opt/${APP_NAME}"

# 2. 参数读取
ENV="${1:-production}"        # ← 第 8 课会讲，先用 $1 理解

# 3. 双引号保护路径
cd "$APP_DIR" || exit 1

# 4. 组合路径时花括号定界
BACKUP_FILE="${APP_DIR}/backups/${APP_NAME}_${TIMESTAMP}.tar.gz"

# 5. 检查退出码
tar -czf "$BACKUP_FILE" "$APP_DIR"
if [ $? -eq 0 ]; then
    echo "备份成功：$BACKUP_FILE"
else
    echo "备份失败！" >&2
    exit 1
fi

8. 参数展开速览（预告）

除了 ${VAR} 基本展开，Bash 还提供了一套"参数展开"语法来处理默认值、字符串截取等：

echo ${VAR:-default}    # 如果 VAR 未设置或为空，用 "default"
echo ${VAR:=default}    # 同上，但还会把 VAR 赋值为 "default"
echo ${VAR:?错误消息}   # 如果 VAR 未设置，打印错误并退出脚本
echo ${VAR:+replaced}   # 如果 VAR 已设置，用 "replaced" 代替原值

FILE="backup.tar.gz"
echo ${FILE%.*}         # → backup.tar  (去掉最短匹配的 .* 后缀)
echo ${FILE##*.}        # → gz          (去掉最长匹配的 *. 前缀)

这些会在后续课程中深入展开。现在你只需要知道它们的存在，看到 ${VAR:-default} 时不会懵。

echo "双引号里 $NAME 展开了"

总结

         ┌──────────────────────────────────────────────┐
         │         变量、引用与展开 速查                   │
         │                                              │
         │  VAR=value         赋值（等号两边无空格）    │
         │  ${VAR}            安全取值（花括号定界）        │
         │  "$VAR"            双引号保护（展开但不分割）     │
         │  '$VAR'            单引号字面（一字不变）        │
         │  $(cmd)            命令替换（现代写法）          │
         │  $?                上一条命令的退出码            │
         │  $1..$9            命令行参数                   │
         │  $@                所有参数（保持独立）          │
         │  $#                参数个数                     │
         │                                              │
         │  黄金法则：变量引用永远加双引号 "${VAR}"      │
         └──────────────────────────────────────────────┘

快速自检

Q1: 下面哪一行会导致错误？

NAME="alice" NAME= "alice" NAME='alice'

Q2: MSG="hello world"; echo $MSG 和 echo "$MSG" 的输出有什么不同？

完全一样，没有区别 无引号会把多个空格压成一个，双引号会保留原始空格 无引号会展开变量，双引号不会展开变量

Q3: 有个部署脚本里看到 LOG_DIR="${APP_HOME}/logs"，花括号 ${APP_HOME} 是必需的吗？

不是，直接写 $APP_HOME/logs 效果一样，花括号只是风格问题 是，因为变量名后面跟着 /，Bash 会把 APP_HOME/logs 整个当成变量名 不，这里不是必需的——但花括号让边界更清晰，是推荐写法

Q4: 你想在脚本里捕获当前时间的字符串，存到变量 NOW 里。正确写法是？

NOW='date' NOW=$(date) NOW="$DATE"
