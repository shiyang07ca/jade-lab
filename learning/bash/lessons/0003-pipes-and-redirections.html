管道与重定向

把简单的命令组合成强大的数据流水线

部署脚本里最常见的两样东西：> log 2>&1 把输出存到日志文件，grep ERROR | wc -l 统计错误数量。这节课就是让你彻底搞懂这些写法。

1. 回顾：三条数据流

第 1 课我们学过——每个进程启动时自带三条流：

          ┌──────────┐
  stdin ──►  进程    ├──► stdout  (fd 1)
  (fd 0)   │          ├──► stderr  (fd 2)
          └──────────┘

默认：stdin ← 键盘，stdout → 屏幕，stderr → 屏幕

重定向就是改变这些箭头的指向：不连键盘/屏幕了，连文件或其他地方去。

2. 输出重定向：把结果存下来

stdout → 文件

echo "hello" > greeting.txt    # stdout 写入文件（覆盖）
cat greeting.txt
hello

echo "world" >> greeting.txt   # stdout 追加到文件末尾
cat greeting.txt
hello
world
记法：> 覆盖（想象一把刀切过去，旧内容没了），>> 追加。都是把 stdout 的输出流指向文件。部署脚本里 >> 更常见——你不会想覆盖掉之前的日志。

stderr → 文件

ls /nonexistent 2> error.log   # stderr (fd 2) 重定向到文件
cat error.log
ls: /nonexistent: No such file or directory

# 同时重定向 stdout 和 stderr
ls /tmp /nonexistent > out.txt 2> err.txt

把 stderr 合并到 stdout

ls /tmp /nonexistent > all.log 2>&1
#                         │      ││
#                         │      │└─ fd 1（stdout 的目标）
#                         │      └── & 表示"文件描述符"（不加 & 会被当成文件名）
#                         └──────── stderr (fd 2) → 指向 fd 1 当前的目标
2>&1 的顺序很重要！2>&1 > file ≠ > file 2>&1。前者把 stderr 指向"当时的 stdout"（还是屏幕），然后再把 stdout 指向文件——stderr 不会进文件。后者先把 stdout 指向文件，再把 stderr 指向 stdout——两者都进文件。先重定向目标，再合并。

3. /dev/null：比特黑洞

ls /tmp > /dev/null           # 输出扔进黑洞，不显示任何东西
ls /tmp > /dev/null 2>&1     # stdout 和 stderr 都扔掉

# 部署脚本里常见的安静模式
curl -s https://example.com > /dev/null
grep -q "ERROR" /var/log/app.log   # -q = quiet，不输出匹配行

/dev/null 是一个特殊文件——写进去的东西直接消失，读它永远返回 EOF。当你只关心命令的退出码而不关心输出时，把输出扔进去。

4. 输入重定向：让命令从文件读数据

wc -l < /etc/passwd            # wc -l 统计行数，stdin 从文件来
45

# 等价于
wc -l /etc/passwd              # 大部分命令直接接受文件名参数
45 /etc/passwd

输入重定向 < 用得较少——大部分命令直接接受文件名。但它和管道配合时非常重要。

5. 管道：把命令串成链

这是 Unix 哲学里最重要的发明：

命令A | 命令B | 命令C
   │      │      │
   └──────┴──────┴── 命令A 的 stdout → 变成命令B 的 stdin → 变成命令C 的 stdin

直观的例子：

ls -la /usr/bin | less        # ls 的输出太长，用 less 分页看

ps aux | grep nginx           # 在所有进程中，筛选出包含 nginx 的行

cat /var/log/app.log | grep ERROR | wc -l
#     │                    │              │
#     输出日志内容         只保留含 ERROR 的行  统计行数
# 最终输出：日志中 ERROR 出现的次数
管道是 Bash 区别于其他编程语言的核心特征。在 Python 里你要写嵌套函数调用或循环——len([l for l in open('log') if 'ERROR' in l])。在 Bash 里，grep ERROR log | wc -l——数据从左往右流过每个命令，每一步都做一件事。这就是 Unix 哲学：每个工具做一件事，管道把它们组合起来。

6. 管道 vs 重定向：别再搞混了

符号 连接的是什么 一端 另一端
| 管道 命令 ↔ 命令 左边命令的 stdout 右边命令的 stdin
> 重定向 命令 → 文件 命令的 stdout 磁盘上的文件
< 重定向 文件 → 命令 磁盘上的文件 命令的 stdin
一个常见误解是以为管道和重定向可以互换。不可以。ls | file.txt 是错的——右边必须是命令。同理，ls > grep foo 也是错的——它把 ls 的输出写进了名叫 grep 的普通文件里。

7. tee：同时写入文件和管道

管道有个问题：数据一经过管道就"消失"了，只能往下游走。如果需要同时把它存到文件并且传给下一个命令，用 tee：

./deploy.sh 2>&1 | tee deploy.log
# 部署脚本的所有输出：
#   → 同时显示在屏幕上（通过 tee 的默认行为）
#   → 同时存入 deploy.log
# 你可以边看输出边保留完整日志！

grep ERROR app.log | tee errors.txt | wc -l
# 筛选出的 ERROR 行：
#   → 存入 errors.txt（方便之后查看）
#   → 同时传给 wc -l 统计数量
部署脚本里的经典写法：./deploy.sh 2>&1 | tee -a /var/log/deploy.log。-a 是追加模式（和 >> 对应），这样每次部署的日志都追加到同一个文件而不是覆盖。

8. 实战组合：几个你马上能用的管道

# 看最占空间的 10 个文件
du -sh * | sort -rh | head -10

# 统计每种文件扩展名的数量
find . -type f | sed 's/.*\.//' | sort | uniq -c | sort -rn

# 查看 22 端口（SSH）有多少连接
netstat -an | grep ':22 ' | grep ESTABLISHED | wc -l

# 统计访问日志里每个 IP 的请求数（top 10）
cat access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10

动手练习（5 分钟）

在终端完成以下任务，体会管道的力量：

# 1. 创建一些测试数据
cat > /tmp/test.log << 'EOF'
INFO  Server started
ERROR Connection refused
INFO  Request handled
ERROR Timeout
WARN  Retry attempt 1
INFO  Shutdown complete
EOF

# 2. 统计 ERROR 出现次数
grep ERROR /tmp/test.log | wc -l

# 3. 把所有错误单独保存，同时在屏幕上显示
grep ERROR /tmp/test.log | tee /tmp/errors.txt

# 4. 模拟"部署脚本"：把输出同时显示和存档
echo "Deploying..." && echo "Done" | tee -a /tmp/deploy.log

# 5. 验证结果
cat /tmp/deploy.log
cat /tmp/errors.txt

总结

           ┌─────────────────────────────────────────┐
           │      管道与重定向速查                     │
           │                                         │
           │  cmd > file       stdout → 文件（覆盖）  │
           │  cmd >> file      stdout → 文件（追加）  │
           │  cmd 2> file      stderr → 文件          │
           │  cmd > file 2>&1  合并 stdout+stderr     │
           │  cmd < file       stdin ← 文件           │
           │  cmd > /dev/null  扔掉输出               │
           │  cmdA | cmdB      A的stdout → B的stdin   │
           │  cmd | tee file   输出到文件 + 继续传递    │
           └─────────────────────────────────────────┘

快速自检

Q1: ./deploy.sh > log.txt 2>&1 和 ./deploy.sh 2>&1 > log.txt 有什么区别？

完全一样，没有区别 前者 stdout 和 stderr 都进文件，后者只有 stdout 进文件 前者只有 stdout 进文件，后者两者都进文件

Q2: 你想统计一个目录下有多少个文件（不含子目录），下列哪条命令可行？

ls | wc ls | grep -c ls | wc -l

Q3: 你只想看某个命令有没有成功（不关心输出），把 stdout 和 stderr 都静默掉。怎么写？

cmd > /dev/null 2>&1 cmd > /dev/null cmd | /dev/null
