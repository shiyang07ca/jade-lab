# 日志分析、失败状态与语言边界

用户通过 mutation testing 补全了 `--top N` 的行为断言，并能应用报告与告警状态、`pipefail`/`SIGPIPE`、
条件函数中的 `errexit`、`!` 状态取反、参数数组和 `exec` 的规则。面对含多行事件、可变时间戳和动态字段的人工
迁移夹具，用户能区分物理行、逻辑事件、严重率分母和消息聚合键，并判断应由 Python 隐藏有状态解析，Bash 只保留
参数与进程编排。用户随后静态走读实际维护的 `thread-count.sh`，并用假 `pgrep`/`ps` 验证成功、无匹配、依赖失败和
进程消失，识别出 `|| true` 合并错误状态与单项时序变化终止批次的问题，并用隔离回归测试完成修复；真实 macOS
`ps -M` 语义仍需在目标环境验证。
