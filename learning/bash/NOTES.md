# Bash 教学规则

## 学习者背景

- 起点是能够使用 `cd`、`ls`、`cat`，但不能稳定阅读和修改部署脚本。
- 每次学习时间约 20–40 分钟，无固定节奏。
- 学习目标是解决真实自动化和部署问题，不追求 Bash 语法覆盖率。

## 教学节奏偏好

- 每次恢复学习时，先说明当前进展、尚未证明的能力、本次目标和接下来的学习顺序。
- 提问前先交代操作对象、必要术语和需要判断的行为，不直接要求追踪尚未讲解的代码。
- 练习应检验 Bash 行为、接口边界或因果关系；避免把难度降成只需复述题干的常识题。
- 一次只推进一个有意义的判断，收到回答后立即反馈，再进入运行验证或下一段代码。
- 保持较快节奏；一个概念经正确应用后立即推进，不用同义问题重复确认。优先使用能暴露真实实现或测试缺陷的综合练习。

## 教学原则

- 从 Shell 的进程、文件描述符、退出状态和参数展开模型解释行为，避免只背命令组合。
- 每个命令都区分 Shell builtin、外部程序和语法结构，并说明它在哪个进程中运行、修改谁的状态。
- 引用、重定向、管道、`set -e`、信号和后台进程必须用最小反例验证；不能用“通常如此”替代边界条件。
- 所有脚本练习使用假凭证、临时目录和可控子进程。调试输出不得包含真实 secret、cookie 或完整环境变量。
- ShellCheck 是静态分析输入，不是正确性证明。重要行为仍需在目标 Shell、目标平台和失败情况下运行验证。
- 学习记录只在学习者能够解释或实际使用知识后创建；课件交付和 Anki 卡片生成不代表掌握。
