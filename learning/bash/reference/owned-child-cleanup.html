受管子进程清理

只处理父 Bash 明确启动并立即记录 PID 的直接子进程

最小状态模型

步骤目的成功不代表
保存 $!记录刚启动任务的 PID任务最终成功
kill -TERM "$pid"发送终止请求目标已经退出
wait "$pid"确认结束并消费等待状态该状态应成为父脚本最终状态
exit 143本课程约定 TERM 中断所有 POSIX Shell 都使用同一映射

处理器骨架

pids=()  # 每次 command & 后立即执行 pids+=("$!")

on_term() {
  local pid child_status
  trap - TERM

  for pid in "${pids[@]}"; do
    if kill -TERM "$pid" 2>/dev/null; then
      printf 'child=%s action=term-sent\n' "$pid" >&2
    else
      printf 'child=%s action=term-not-sent\n' "$pid" >&2
    fi
  done

  for pid in "${pids[@]}"; do
    if wait "$pid" 2>/dev/null; then
      child_status=0
    else
      child_status=$?
    fi
    printf 'child=%s wait_status=%s\n' \
      "$pid" "$child_status" >&2
  done

  exit 143
}

trap on_term TERM
先向全部 PID 发送 TERM，再逐项 wait。不要在第一个仍运行的子进程上先等待，否则后续子进程迟迟收不到 终止请求。

验证清单

  • 测试等待所有 PID 已记录，再只向父 PID 发送 TERM。
  • 父脚本状态符合公开接口；本课程固定为 143。
  • 每个受管 PID 都已执行 wait，测试结束时均不存在。
  • 正常完成、运行中中断、部分任务已结束时中断分别验证。
PID 数组不等于进程树。子进程自行创建的后代、忽略 TERM、超时升级、连续信号和自动重启均不由这段骨架解决。
