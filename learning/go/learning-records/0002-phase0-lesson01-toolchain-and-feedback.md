# Phase 0 第 1 课：工具链与最小反馈

日期：2026-09-11

## 目标与背景

本课使用 Go 1.26.5 建立最小反馈流程：运行程序、格式化、静态检查、测试、竞态检测和构建；同时从一个小函数观察 map 的零值行为。学习者有 Python/Django 后端经验，Go 语法已有简要了解，本课不重复 HTTP、SQL 或 Python 入门。

## 练习与理解证据

- 学习者运行 `mise exec go@1.26.5 -- env GOTOOLCHAIN=local go env GOMOD GOVERSION`，得到课程 module 的 `go.mod` 路径和 `go1.26.5`。
- 学习者运行 `go run ./lesson01`，得到 `map[go:4 python:1]`。
- 学习者把测试期望中的 `"go": 2` 临时改为 `"go": 3`，测试实际报告 `got map[go:2 python:1]`、`want map[go:3 python:1]`，证明测试确实检查了目标行为；随后已恢复为 `2`。
- 在讲解后，学习者回答“不存在的 map 默认为 0”。这支持对 `map[string]int` 缺失键零值的初步理解，不是所有 map 的值都为 `0`，也尚无独立变体应用证据。
- 教师检查了恢复后的 `main_test.go`；教师运行 `go test -race ./lesson01` 返回缓存成功，随后仓库级检查中的非缓存测试通过。这不等于学习者独立完成所有检查。
- 学习者对 `-race` 的初步解释是“会测试出并发问题，需要原子操作才行；同步顺序访问可以避免”。其中“检查并发问题”成立；原子操作不是唯一方案，map 常用互斥锁，或由单个 goroutine 独占并通过 channel 交互。仅凭代码书写顺序不能保证并发安全。该区别已讲解，尚未通过变体练习独立验证。
