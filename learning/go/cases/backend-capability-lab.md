# 后端能力实验：从 HTTP 到可运行服务

返回[案例索引](../CASES.md)。实验可删除，不虚构长期产品，用于练习独立实现、测试和部署 Go 后端。
不要求开始时理解全部功能，也不提前搭建所有抽象。

## 代码归属

开始实现时在根目录 `labs/scheduling/job-intake-go/` 使用独立 Go module 和 README。
实现、迁移和测试只保留在那里，学习目录保存说明和链接。实验不导入 Dagu 内部包，不仿制工作流引擎。
后续是否长期保留按实际价值决定。

## 逐步增加的行为

1. 最小 HTTP：用 `net/http` 实现一个明确接口，学习 JSON、输入验证、错误响应和 `httptest`。
2. 数据持久化：使用真实 PostgreSQL 18，加入迁移、约束、事务和资源清理，验证重启后数据仍存在。
3. 后台处理：理解普通请求后，再解释不要求客户端保持连接等待的工作，选择具体、受控的练习任务。
   届时定义提交、查询和取消行为，不预设抽象分批计算或产品需求。
4. 有限并发与关闭：先通过小例子理解同步和取消，再加入执行数量上限、等待容量、停止接纳和等待或取消现有工作。
5. 最小部署：在本机 Linux 容器环境运行服务与 PostgreSQL，验证构建、配置、迁移、健康检查、日志、
   优雅停止及重启后的数据状态；持久数据不能只留在容器可写层。

进入后台阶段后再确定 API 路径、状态、重复提交、事务领取、重试和取消规则。届时用并发测试验证是否重复领取，
根据具体规则选择 SQL，不提前固定存储抽象或队列算法。暂未选择任务内容不阻断语言与 HTTP 学习。

## 需要验证的工程行为

- 无效输入不会进入业务处理；HTTP 成功和失败响应可测试。
- 真实 PostgreSQL 验证迁移、约束和事务，不用内存实现替代数据库检查。
- 引入并发后，任务数量、取消、关闭和 goroutine 结束有明确行为与测试；`-race` 通过不代表所有并发问题都不存在。
- 静态检查、测试和构建通过；能结合自己的代码解释失败过程或修改一个条件。
- README 支持重复启动、迁移、停止及数据恢复验证，不包含真实凭证。

这些用于指导开发和阶段性检查，不是每个知识点的考试。教学顺序见[课程路线](../CURRICULUM.md)。

## 不在核心范围

- Web UI、认证产品化、ORM、Redis、Kafka、Kubernetes、通用编排或多租户。
- 公网服务器、域名和完整公网运维；本机容器部署不证明这些能力。
- Gin 替换仅为选修，选择时复用应用逻辑和测试。
