# Go 学习路线：从必要基础到后端交付

以独立交付为主，兼顾求职，通过真实维护练习能力。目标见 [MISSION.md](MISSION.md)，教学方式见
[NOTES.md](NOTES.md)，固定版本和源码入口见 [CASES.md](CASES.md)。约 50 小时是投入参考，不是阶段截止时间。

## 核心路线

| 阶段 | 主要内容 | 实际产物 |
| --- | --- | --- |
| 1. 必要语言基础（当前） | 声明与类型、函数、值与指针、结构体、slice/map、错误和基本测试；按表现补语法 | 能自己修改的小程序和测试 |
| 2. 最小 HTTP 服务 | `net/http`、JSON、输入验证、错误响应、包与模块；需要替换依赖时再讲接口 | 可调用、可测试的接口 |
| 3. 数据持久化 | PostgreSQL、SQL 调用、迁移、约束、事务、连接与资源清理 | 重启后数据仍然存在的服务 |
| 4. 并发与生命周期 | 小例子中的 goroutine、同步、取消，再引入有限后台处理和关闭 | 有明确执行与停止行为的实验 |
| 5. 最小交付 | 构建、Linux 容器、配置、健康检查、日志、迁移、停止和重启 | 有运行说明、可重复启动的服务 |
| 穿插进行 | 根据当前问题阅读 leetgo 或 Dagu；基础足够时完成一项真实修改 | 必要的调用说明、失败测试和可评审改动 |

不要求先学完所有语言机制再写服务。接口、错误包装、并发和资源生命周期在实际使用时继续深入；难以理解的
行为先拆成短例子，不在服务中同时堆入多个未知概念。后端范围见[实验说明](cases/backend-capability-lab.md)。

## 当前单元

从第 1 课的 `countWords` 小函数继续，通过一次小变更理解类型、值和参数传递。已有程序运行和测试失败恢复
证据，不重新布置整套工具安装。当前学习记录见
[第 1 课记录](learning-records/0002-phase0-lesson01-toolchain-and-feedback.md)。

下一次开始时：

1. 结合已有函数说明参数类型、返回类型、局部类型推断和 map 值类型的零值。
2. 示范一个独立的小例子，说明函数参数接收的是值的副本；区分复制普通值与复制仍指向共享数据的值。
3. 让学习者预测一个结果或修改一个条件，再用运行结果讨论原因。具体变更随当次理解选择，不提前给出完整答案。

暂不追问尚未解释的同步方案，不用竞态知识作为学习值语义的考试。第 1 课 HTML 仅为参考，不是必读前置材料。

## 真实源码怎样使用

- [leetgo](cases/leetgo.md)：需要观察 CLI、配置、错误、HTTP 客户端、文件或测试时，选择相关调用路径。
- [Dagu](cases/dagu.md)：需要观察任务执行、取消、状态、日志或关闭时定向阅读；实际工作流按需要使用。
- 第一轮至少完成一项可评审修改，优先来自实际使用问题；若候选不适合，换题，不阻断后端主线。
- 不按目录通读，也不要求案例文档中的每条路径都完成。缺陷修改先复现并建立测试，再实现修复。

## 阶段性反馈

完成一段有实际意义的功能后，结合代码解释关键行为、改变一个条件或定位一个问题，允许查资料。
结果只用于判断下一步补什么，不评分，不逐知识点设置结束条件。运行教师给出的程序不等于独立应用。
并发、事务和关闭等行为仍需要测试，不能只凭口头解释判定正确。

代码与测试保存行为；学习记录只保存重要纠正、实际证据和下次入口，不复制对话或另设进度表。
只细化当前单元，不预制后续全部练习。环境故障由教师协助处理，不把排障等待当作主动学习。

## 选修与后续

完成核心交付后，按实际需求选择 Gin 对照、Dagu 分布式 worker/gRPC、深入性能诊断或
[Nuclei 网络并发比较](cases/nuclei.md)。选修不影响核心路线继续，也不要求一次全部完成。
公网部署、安全配置、升级和故障恢复可以作为后续实践；本机容器部署不证明完整公网运维能力。
