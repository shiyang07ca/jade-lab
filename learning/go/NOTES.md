# Go 教学规则

## 学习者背景

- 有 Python/Django 后端经验，已经理解 HTTP、路由、中间件、ORM 和一般 SQL 概念。
- 简要了解 Go 语法，但尚不能熟练实现、诊断和维护 Go 项目。
- 学习动机是技术储备、求职和独立构建 Go 后端服务；关注量化金融、AI 开发者工具和安全方向，但课程先覆盖
  通用 Go 岗位所需能力。
- 每次学习 20–50 分钟，无固定日程。累计时间是安排工具，不是掌握程度的证明。

学习目标和表现标准只在 [MISSION.md](MISSION.md) 维护；课程顺序只在 [CURRICULUM.md](CURRICULUM.md) 维护；
版本与源码路径只在 [CASES.md](CASES.md) 及 `cases/` 维护。

## 教学原则

- 从值、状态、生命周期、失败和资源限制推导行为，再学习语法或框架 API；先问“语言保证什么”，再问“项目如何选择”。
- 与 Python/Django 做精确比较，但不使用“Python 隐式、Go 显式”一类不能预测实际行为的口号。
- 每次 20–50 分钟仅为参考，围绕一个具体问题讲解和动手，不用任务填满时间，不设置固定试学或打卡流程。
- 编辑器动手为主，对话解释必要知识，短笔记用于续学。既有 HTML 仅供参考，不预制整套课程页面。
- 教师处理环境排障和必要骨架；学习目标对应的代码由学习者尝试。卡住时先给有效提示，必要时直接示范解法。
- 先讲清再练习，允许查文档，不追问尚未解释的概念。按需要回顾，不强制每次背诵或运行旧测试。
- 完成有意义的功能后结合代码解释、变更或诊断进行阶段性检查，不评分、不逐知识点设结束条件。
- 只记录重要纠正、实际证据和下一步；教师检查与学习者独立应用分开记录，课件、源码阅读和累计时间不是掌握证据。
- 语言事实先查固定版本的 Go 规范、官方文档和标准库。项目行为必须注明 commit，并用调用方、测试或运行结果核对。
- 缺陷修复先复现并建立失败测试，再修改代码；普通练习不机械要求先写失败测试。真实 issue 优先来自实际使用；开放 issue 必须在开始当天重查状态、已有 PR、
  固定版本复现和任务范围。
- 并发练习必须有数量上限、取消、等待和结束规则，并运行 `go test -race`；只有自包含的时间与并发行为才考虑
  `testing/synctest`。
- HTTP、网络、文件和数据库输入视为不可信。检查请求体上限、严格解码、timeout、响应体关闭、`Rows`/`Tx`
  结束以及错误是否保留原因。
- 性能结论必须记录 Go 版本、平台、输入、benchmark 次数和原始结果；使用 `benchstat` 时还要记录其版本；
  没有测量不做优化结论。
- 核心用 `net/http` 完成交付；Gin 对照为选修，选择时复用应用逻辑和测试，不复制业务代码。
- 持久化阶段使用真实 PostgreSQL 18 验证约束和事务，不能用 map 或 mock 数据库替代。
- 安全实验只使用本地夹具或明确授权目标；不处理真实资金、私钥、生产凭证或未经授权的公网扫描。

## 必须避免的错误表述

- 不把 Go 的诞生归因于“三位作者等待 C++ 编译”这一个故事；历史陈述以 Go 官方 FAQ 为准。
- 不说 Python 的哲学是“隐式最好”；Python 的 Zen 明确写有 “Explicit is better than implicit”。
- 不把 CPython GIL、解释执行或部署方式描述为所有 Python 实现共同拥有的语言规则。
- 不说 Go 程序总是完全静态且只需单文件；cgo、动态库、证书和外部资源会改变部署要求。
- 不说 `go get` 用于安装命令；现代 Go 使用 `go install package@version`。
- 不把 `go vet` 称为编译阶段；它是独立静态分析工具。
- 不把 `gofmt` 称为编译器强制；格式要求由工具和项目检查执行。
