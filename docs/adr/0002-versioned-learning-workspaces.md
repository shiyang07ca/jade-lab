# 使用版本受控的学习工作区

## 背景

`.scratch/` 被 Git 忽略，并承担本地票据、临时验证和机器相关状态。Go 与 Bash 的学习使命、课件、资料索引和
学习记录此前也存放在该目录，导致长期材料没有版本历史，并且临时状态与需要维护的课程内容难以区分。

现有 `labs/`、`packages/` 和 `tools/` 按可执行内容的调用方式和验证程度组织，`docs/` 保存仓库级结论；它们都不适合同时
保存个人学习使命、课程顺序和掌握证据。

## 决定

- 新增顶层 `learning/`，按稳定学习主题组织，每个主题维护一个当前使命。
- 学习工作区保存使命、课程、资料索引、教学规则、课件和已经由实际表现支持的学习记录。
- 与某一课及其评分标准共同演进的最小练习可以进入 `learning/<topic>/exercises/`；需要独立环境或能够脱离课程回答
  问题的代码进入根 `labs/`，稳定产物再按调用方式进入 `packages/` 或 `tools/`。
- 外部项目源码不复制到学习工作区；只有长期保留时才进入 `references/` submodule，其他情况按明确 commit
  获取到仓库外目录或 `.scratch/`。
- 构建缓存、完整日志、机器环境和未决定是否保留的草稿继续留在 `.scratch/`。

## 影响

- Go 与 Bash 学习材料进入 Git 历史，可以审查课程变化并在不同机器恢复。
- 学习目标和记录可能随仓库公开；仓库所有者已明确接受公开这些内容。
- 新增课程前必须先写出具体使命和成功表现，不能把 `learning/` 当作通用笔记目录。
- 学习成果是否迁移到其他模块由其实际运行和复用情况决定，不由课程章节决定。
